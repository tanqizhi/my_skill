# 服保短反馈模板

本模板适用于OLT、MSE或AAA任一系统排查完成后直接回填服保。OLT示例中的字段可按实际系统替换。正文必须控制在500个字符以内，建议使用单段文本，避免复制详细分析内容。

## 通用模板

```text
【{系统}排查】设备/对象：{设备或用户标识}；已查：{本次实际查询项目}。结论：{正常/明确异常/疑似异常/信息不足}；证据：{关键字段、数值或告警}。下一步：{继续排查的系统及目的/执行的人工操作/无需继续排查}。派单：{无需派单/目标地市或组织+岗位}；要求：{需完成的具体事项}。
```

## OLT示例：需要现场处理

```text
【OLT排查】设备：株洲某OLT/用户A；已查：ONU注册、在线状态、光功率、端口、业务配置及告警。结论：明确异常；证据：ONU离线，OLT侧有LOS告警，疑似接入光路中断。下一步：现场核查用户端设备、尾纤及接入光缆。派单：株洲市分公司政支/装维；要求：上门查障，测试并反馈光功率、现场照片及处理结果。
```

## MSE示例：需要云网调度中心处理

```text
【MSE排查】设备：某MSE/用户B；已查：用户会话、接口状态、设备告警及相关计数。结论：明确异常；证据：业务接口出现持续丢包/告警，影响用户接入。下一步：核查MSE接口及上联链路。派单：云网调度中心；要求：处理MSE及上联链路异常，反馈原因和恢复结果。
```

## AAA示例：继续核查认证系统

```text
【AAA排查】系统：AAA/用户C；已查：账号状态、认证记录、认证结果及策略匹配。结论：疑似异常；证据：认证请求失败，返回码为{代码}，设备侧链路正常。下一步：继续核查AAA策略、账号及认证链路。派单：无需派单。
```

## 生成规则

1. “系统”填写OLT、MSE或AAA；“已查”只列实际执行的项目，不得把未执行项目写成已完成。
2. “证据”优先保留能支持结论的状态、数值、告警、返回码和时间信息。
3. 现场上门或客户侧配合派对应地市分公司政支/装维；OLT层面操作派对应地市分公司网操；MSE、SR、CR、D、传输或相关关键设备问题派云网调度中心；AAA问题按实际归属岗位派单。
4. 字符接近500时，压缩设备描述和背景，保留结论、证据、下一步及派单要求；不得删除派单岗位或具体处理事项。
