# OLT服保反馈模板

本模板用于OLT排查完成后直接回填服保。正文必须控制在500个字符以内，建议使用单段文本，避免复制详细分析内容。

## 模板

```text
【OLT排查】设备：{OLT/用户标识}；已查：{ONU注册/在线状态、光功率、端口状态、业务配置、告警及计数等实际项目}。结论：{正常/明确异常/疑似异常/信息不足}；证据：{关键字段、数值或告警}。下一步：{继续排查的系统及目的/执行的人工操作/无需继续排查}。派单：{无需派单/目标地市或组织+岗位}；要求：{需完成的具体事项}。
```

## 示例：需要现场处理

```text
【OLT排查】设备：株洲某OLT/用户A；已查：ONU注册、在线状态、光功率、端口、业务配置及告警。结论：明确异常；证据：ONU离线，OLT侧有LOS告警，疑似接入光路中断。下一步：现场核查用户端设备、尾纤及接入光缆。派单：株洲市分公司政支/装维；要求：上门查障，测试并反馈光功率、现场照片及处理结果。
```

## 示例：需要OLT操作

```text
【OLT排查】设备：衡阳某OLT/用户B；已查：ONU注册、光功率、端口、业务配置及告警。结论：疑似异常；证据：ONU已注册但业务端口异常，未见光功率越限。下一步：核对业务数据并补查上联。派单：衡阳市分公司网操；要求：核查OLT端口/业务状态，按审核步骤处理并反馈结果。
```

## 示例：OLT侧正常，转其他系统

```text
【OLT排查】设备：长沙某OLT/用户C；已查：ONU注册、在线状态、光功率、端口、业务配置及告警，未见异常。结论：OLT侧正常，暂不能解释故障。下一步：继续排查MSE/SR及传输链路。派单：无需派单。
```

## 生成规则

1. “已查”只列实际执行的项目，不得把未执行项目写成已完成。
2. “证据”优先保留能支持结论的状态、数值、告警和时间信息。
3. 现场上门或客户侧配合派对应地市分公司政支/装维；OLT层面操作派对应地市分公司网操；MSE、SR、CR、D或传输问题派云网调度中心。
4. 字符接近500时，压缩设备描述和背景，保留结论、证据、下一步及派单要求；不得删除派单岗位或具体处理事项。
