# 结果判断、异常处理与管理员版切换

## 一、结果判断全表

| 结果 | Agent 行为 |
| --- | --- |
| HTTP 200、`completed`、退出码 0 | 继续检查输出内容、stderr 和预期结果；不能直接宣布修复 |
| `completed`、退出码非零 | 记录错误，判断权限、命令参数或系统状态，不盲目重试 |
| `timed_out` / `cancelled` | 视为可能部分执行，先核对现状；已完成的修改不会自动回滚 |
| `launch_failed` | 未运行本次用户脚本，检查运行环境或请求人工处理 |
| HTTP 409 | 实例已有命令，查询状态并等待或请工程师确认，不建立重试队列 |
| HTTP 400 / 413 / 415 | 检查请求格式、体积和类型，修正后作为新的明确请求处理 |
| HTTP 403 / 404 / 405 | 检查地址、转发端口、Host、Origin、路径或方法，不绕过访问约束 |
| HTTP 408 / 411 | 检查请求体发送过程和 Content-Length；仅在明确未启动脚本时修正后重新提交 |
| HTTP 500 | 阅读错误字段；若不是明确的 `launch_failed`，按执行状态不确定处理 |
| HTTP 503 / `unhealthy: true` | 程序停止中或进程清理异常，交由工程师检查，不绕过限制继续发命令 |
| 重定向、非 JSON 或协议字段异常 | 停止，检查是否连到了其他服务，不跟随到新地址 |
| 连接断开、HTTP 超时、响应解析失败 | 标记结果未知，不自动重发 POST，先恢复连接并核对实际状态 |
| 输出被截断 | 缩小只读查询范围或分批读取；不为获得输出重复执行变更命令 |
| 目标权限不足 | 说明缺少的权限，请工程师决定是否切换管理员版 |
| 不支持的架构、镜像、组件缺失 | 停止兼容性尝试，整理信息转人工 |
| 启动提示 `PATHEXT has no .EXE` | 当前环境变量异常，交给工程师检查，不自动修改系统或用户环境变量 |

## 二、判定纪律

HTTP 200 不等于命令成功，命令成功不等于故障已经解决。任何执行响应附带 `error`，特别是 `stdin_incomplete` 或 `output_read_failed` 时，都不能忽略；输出可能不完整，需人工判断。修复验证应对应原始故障现象，并在需要时由客户确认。

允许在恢复连接后重新查询 health；它只能告诉你当前状态，不能追回丢失的命令结果。即使 `busy` 变成 false，也不能推断上一次命令成功或未执行。

## 三、切换管理员版

1. 说明需要更高权限的具体原因，请工程师确认。
2. 确认当前执行已结束，关闭普通版。
3. 由工程师或客户打开 `CloudDiagBridge.Admin.exe`，按系统要求完成 UAC。
4. 读取新窗口端口，必要时修改 RustDesk 远端目标端口。
5. 重新查询 health，核对机器名及 `is_elevated`。
6. 重新核对执行账户；使用其他管理员凭据时，不要把管理员的用户目录或 HKCU 当成客户原账户的数据。
7. 在授权范围内继续诊断，不自动重放之前失败或结果未知的命令。

普通版默认不申请提权，但实际权限取决于启动环境。管理员版不能保证每次都弹窗，UAC 提示受系统策略和已提升状态影响。始终检查实际权限，不以文件名替代检查。
