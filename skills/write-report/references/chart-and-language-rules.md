# 图表与语言规则

## 按目的选图

| 目的 | 优先图型 | 注意事项 |
|---|---|---|
| 显示随时间变化 | 折线图、区间带 | 标明异常点、事件和数据缺口 |
| 比较对象或方案 | 排序条形图、点图 | 使用同一口径与零点；避免 3D |
| 显示达标情况 | 子弹图、实际值与阈值对照 | 明示目标、阈值及方向 |
| 显示分布或波动 | 箱线图、直方图、分位点图 | 同时写样本量与分位口径 |
| 显示构成 | 100% 堆叠条形图、少类别饼图 | 类别过多时改用排序条形图 |
| 显示流程或时间线 | 时间线、简洁流程图 | 只保留决策相关节点 |
| 显示关系 | 散点图 | 不把相关性写成因果关系 |

优先使用一个能直接支撑开篇结论的决定性视觉。大量详细趋势图和所有次要图放到第 3 页以后或附录，不要缩小后堆在前两页。

## 每张图的强制说明

紧跟图表写两项：

- `看到什么`：只描述图中直接可见的趋势、差异、峰值、异常或达标情况。
- `意味着什么`：说明它对当前问题或决策的意义，并保留适用边界。

若无法写出这两项，删除图表或更换图型。标题写结论性信息；坐标、单位、图例、时间范围和数据源必须清楚。颜色保持少量且含义一致，不只靠红绿区分。

## 数据诚实

- **事实**：数据、日志或已确认记录直接支持；使用“数据显示”“记录表明”。
- **推断**：由事实推导但尚未直接验证；使用“可能”“与……一致”“推测”。
- **未知**：数据缺失、范围未覆盖或口径不明；写清未知内容及其对结论的限制。

不得补造缺失值、样本量、基线、阈值、原因或业务影响。不得把平均值替代 P95，也不得把零观测写成绝对不会发生。

## 面向非技术领导的语言

先说结果和业务含义，再说技术名词。句子保持短而具体，删除套话、重复结论和未经证实的形容词。

不可避免的术语在首次出现时行内解释，例如：`P95 时延（95% 的样本不超过该值）`。只有术语反复出现时才在文末设置术语表。前两页附近最多保留 3–5 个真正影响理解的关键术语，不另建大段术语章节。

把指标的通俗解释写成决策含义，而非换一种方式重复数字。例如：

- `丢包率 0%` → `本次采集窗口未观察到数据包丢失，不代表未测试场景永远无丢包。`
- `吞吐率 95%` → `实测传输能力达到参考值的 95%；是否达标仍取决于预先定义的阈值。`
- `帧率匹配率 99.9%` → `本次条件下发送与呈现节奏几乎一致；未覆盖环境不能据此外推。`
