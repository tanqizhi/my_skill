# 交付审查清单

逐项检查；任一硬性项不满足时继续修改并重新渲染。

## 文件与可编辑性

- [ ] 最终只交付 `.docx`。
- [ ] 已使用 `documents` 技能及其工作区运行时流程。
- [ ] `assets/technical-report-template.docx` 存在且已使用；若不存在，已明确失败而非替换模板。
- [ ] 正文和表格保持可编辑；图表优先可编辑，图片图表带有配套数据表和明确替换位置；没有用整页图片伪装成报告。

## 事实与口径

- [ ] 时间范围、对象、环境、范围、数据来源、方法、持续时间和样本量均有依据；缺失项明确标为未知。
- [ ] 事实、推断和未知明确区分。
- [ ] 未编造缺失数据、阈值、基线、原因或影响。
- [ ] 指标定义、单位、分位口径和比较口径一致。
- [ ] 结论未外推到未覆盖的时间、区域、负载、版本或环境。

## 两页执行报告

- [ ] 第 1–2 页可独立阅读并完成汇报。
- [ ] 没有独立封面或目录占用前两页。
- [ ] 第 1 页含报告时间、数据时间范围、范围/边界、对象/环境的紧凑元数据。
- [ ] 第 1 页含一句话结果，且结果带适用条件。
- [ ] 第 1 页含 3–5 个关键指标，表头为 `指标 | 结果 | 通俗解释`。
- [ ] 第 1 页含且只突出一个最有决策价值的视觉。
- [ ] 该视觉后立即出现 `看到什么` 与 `意味着什么`。
- [ ] 第 2 页含决定性证据，并已按报告类型选择比较、时间线、影响范围等合适形式。
- [ ] 第 2 页含数据来源、方法、持续时间、样本信息和适用边界。
- [ ] 行动或建议仅在有依据时出现，没有为形式完整而强行添加。

## 第 3 页以后

- [ ] 技术证据与附录从第 3 页开始。
- [ ] 方法细节、完整趋势、大量详细图和所有次要图、原始数据映射和术语表已下沉。
- [ ] 摘要、总体结果、负载章节和专项章节没有重复复述同一内容。
- [ ] 故障、测试或对比型报告采用了对应证据结构。

## 图表与语言

- [ ] 图型与目的匹配，标题、坐标、单位、图例、时间范围和来源清楚。
- [ ] 每张图后都立即解释 `看到什么` 和 `意味着什么`。
- [ ] 相关性没有被写成因果关系。
- [ ] 先使用通用语言；不可避免的术语首次出现时已行内解释。
- [ ] 前部术语不超过 3–5 个且确有必要；反复出现的术语才进入文末术语表。
- [ ] 通俗解释给出决策含义，而非机械复述数字。

## 渲染与分页

- [ ] 已按 `documents` 技能要求渲染 DOCX 的每一页，而非只抽查前两页。
- [ ] 已逐页检查分页、孤行、溢出、遮挡、裁切、空白、表格断裂和图表可读性。
- [ ] 前两页预算通过实际渲染确认，不是按字数猜测。
- [ ] 未通过缩小正文字号、压缩行距或降低可读性强行塞入两页。
- [ ] 超出预算的重复或次要内容已删除、聚合或移到第 3 页以后。
- [ ] 最终重渲染后仍满足全部检查项。
