# 报告类型

先选最符合任务的一种主类型；混合任务可组合，但不要复制章节。第 2 页放决定性证据，并按类型选择比较、时间线、影响范围等合适形式。

## 故障 / 事件报告

### 前两页重点

- 第 1 页：事件影响、当前状态、最关键业务指标、影响随时间变化的决定性视觉。
- 第 2 页：决定性证据，优先选择关键时间线、影响范围或受影响/未受影响对象，随后说明证据来源、确认范围和尚未确认事项；有依据时再写处置或后续行动。

### 技术证据

记录事件时间线、症状、检测方式、处置、恢复验证、根因证据和遗留未知。仅把证据闭环支持的内容称为根因；否则标为推断或待确认。

## 测试 / 评估报告

### 前两页重点

- 第 1 页：测试对象与条件、是否达到目标、3–5 个决定性指标、最能代表整体结果的视觉。
- 第 2 页：以工作负载或基线比较作为决定性证据，并说明数据来源、测试方法、持续时间、样本量、覆盖与未覆盖场景。

### 技术证据

记录环境、配置、指标口径、采样与清洗方法、重复次数、分组数据、完整趋势和异常。只对实际测试条件下的结果作结论，不外推到未覆盖环境。

## 对比报告

### 前两页重点

- 第 1 页：比较对象、共同口径、一句话差异结论、3–5 个同口径指标和最有区分度的视觉。
- 第 2 页：以决定性差异作为核心证据，并说明数据可比性、采样窗口、版本/环境差异、不可比项和决策边界。

### 技术证据

记录各对象配置、口径对齐、归一化方法、逐项差异和敏感性。不得把不同时间窗、环境或定义下的数据直接当作同口径结论。

## 技术发现 / 性能 / 网络报告

把发现、性能或网络现象归入最接近的上述结构：验证目标时采用测试型；比较版本、链路或方案时采用对比型；解释异常影响时采用故障型。第 3 页以后再展开时延分位数、吞吐、丢包、资源、拓扑、日志与原始趋势。

## 建议规则

把建议视为可选内容。只有当证据能说明问题、行动对象和预期影响时才提出；否则报告事实、边界与未知即可。不要为形式完整而强行给出扩容、改造、采购或推广建议。
