# 写报告

把技术数据组织成领导可直接阅读、汇报和修改的中文 Word 报告。先交付可独立阅读的两页执行报告，再提供技术证据。

## 执行流程

1. 收集报告目的、读者、数据、口径、时间范围、范围边界和来源。把内容标记为事实、推断或未知；不得补造缺失数据。
2. 根据报告类型读取 [report-types.md](references/report-types.md)，并读取 [chart-and-language-rules.md](references/chart-and-language-rules.md)。
3. 使用已安装的 `documents` 技能及其工作区运行时，严格执行其 DOCX 创建、编辑、渲染和验证流程。
4. 检查 `assets/technical-report-template.docx`。模板存在时以它为基础；模板缺失时立即明确失败：`缺少 assets/technical-report-template.docx，无法按指定模板生成报告。` 不得静默改用自制模板。
5. 仅生成 `.docx`，保持文本和表格可编辑。图表优先使用可编辑形式；若只能插入图片，同时保留图表数据表和清晰的替换位置。不得以 PDF、整页图片或仅 Markdown 代替最终交付物。
6. 按下述硬性两页预算编排内容，再把技术证据放到第 3 页及以后。
7. 渲染 DOCX 的每一页并检查分页、溢出、遮挡、图表可读性和两页预算。调整内容层级并重新渲染，直至通过。
8. 交付前逐项执行 [review-checklist.md](references/review-checklist.md)。

## 硬性两页预算

把前两页视为完整的执行报告；读者不看第 3 页以后也必须能理解结论、证据强度和适用边界。不得用独立封面或目录占用前两页。

### 第 1 页：结论看板

按以下顺序放置：

- 紧凑元数据：报告时间、数据时间范围、范围/边界、对象/环境。
- 一句话结果：直接回答“结果是什么”，同时限定适用条件。
- 3–5 个关键指标表：固定为 `指标 | 结果 | 通俗解释`。
- 一个最有决策价值的视觉；紧接视觉写 `看到什么` 与 `意味着什么`。

只选最能支撑一句话结果的视觉。不得让多张次要图挤占第一页。

### 第 2 页：证据与边界

放置决定性证据（按类型选择比较、时间线、影响范围等）、数据来源/方法/持续时间/样本，以及已覆盖与未覆盖边界。仅在有依据且有决策价值时放行动或建议；不得强行给建议。

### 第 3 页及以后：技术证据

承载方法细节、完整趋势、分组结果、异常记录、原始数据映射、术语表和附录。合并重复的指标、工作负载和结果章节；不要在摘要、总体结果和专项章节反复复述同一结论。将所有次要图和其他次要材料下沉到后续页面或附录。

不得通过缩小正文字号、压缩行距或牺牲可读性强行塞入两页。超出预算时删减重复表达、聚合内容或下沉次要证据。

## 图表与表达

- 按问题选择图型，而非按现成数据选择装饰效果。
- 每张图后立即解释 `看到什么` 和 `意味着什么`；没有解释的图不得保留。
- 先用通用语言。不可避免的术语在首次出现时行内解释；重复较多时在文末增设术语表。
- 仅在确有必要时于前两页附近解释 3–5 个关键术语。
- 明确区分事实、推断和未知。缺数据时写明未知项及影响，不得估算成事实。

## 完成标准

只在每页均已渲染检查、前两页能独立成立、所有图表都有即时解读、正文和表格可编辑且不可编辑图表带有数据表时交付 `.docx`。
